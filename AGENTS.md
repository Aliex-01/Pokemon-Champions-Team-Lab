# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project

Pokémon Champions Team Lab — a personal VGC (Reg M-B, doubles) team-building web app: team builder, Speed Tier, Pokédex, damage calculator, type coverage, EV optimizer, meta builds, replay analysis, and tournament teams. React 19 + TypeScript + Vite + Tailwind CSS v4, deployed as a static site on Cloudflare Pages with a serverless backend (Cloudflare Pages Functions + D1) for user accounts only.

## Commands

```bash
npm install
npm run dev              # http://localhost:5173 — Cloudflare Functions do NOT run here
npm run build             # generate-data + generate-tournament-teams + generate-og + tsc -b + vite build
npm run lint               # eslint .
npx tsc --noEmit           # typecheck only (faster than full build during iteration)
```

There is no test suite/runner in this repo. Verify changes with `npx tsc --noEmit`, `npm run lint`, and `npm run build`.

Individual data generators (each writes into `public/data/`, safe to run standalone):
```bash
npm run generate-data              # public/data/champions.json, builds.json
npm run generate-tournament-teams  # public/data/tournament-teams.json
npm run generate-og                # public/og-image.png, PWA icons
```

To exercise the Functions backend (login, `/api/pokepaste` proxy) locally, build first then run `npx wrangler pages dev dist` — `vite dev` alone does not serve `functions/`.

## Architecture

**Data is precomputed, not fetched live.** Everything the UI shows (legal roster, learnsets, move/ability/item data, Smogon usage stats, tournament teams) is generated by Node scripts in `scripts/*.mjs` *before* the build and written to `public/data/*.json`. The app loads these with `fetch` at runtime (`src/lib/championsData.ts`, `src/lib/metaBuilds.ts`) — there are no live API calls to PokeAPI/Smogon/Showdown from the browser during normal use. The only live backend calls are `/api/*` (Cloudflare Functions) for accounts, and `/api/pokepaste` as a CORS proxy for importing a Poképaste by URL.

```
scripts/generate-data.mjs  ──→ public/data/champions.json, builds.json
scripts/generate-tournament-teams.mjs ──→ public/data/tournament-teams.json
                                                │
                                                ▼
                                    src/lib/championsData.ts (fetch + cache)
                                                │
                                                ▼
                                          src/views/*.tsx
```

- `scripts/generate-data.mjs` uses `@pkmn/dex` + `@pkmn/mods/champions` for the dex/learnsets/moves/abilities/items, filters the legal roster via `scripts/allowed-nums.txt` (Pokédex numbers) and assigns tiers from `scripts/tiers.json`, adds Spanish names from PokeAPI, and pulls Smogon usage stats (chaos JSON) for `builds.json`. It also fixes up megas whose `baseSpeciesId` points at a species not present in the format (e.g. Floette-Mega → base "Floette" doesn't exist in the roster, only "Floette-Eternal") by remapping to the present same-Pokédex-number form.
- `scripts/generate-tournament-teams.mjs` scrapes a public Google Sheet (one gid per regulation tab) maintained by VGCPastes; team IDs are prefixed per regulation (`PC` = M-A, `MB` = M-B — extend the regex when a new reg adds a new prefix).
- Regenerating data (`npm run build`) is what picks up Smogon Reg M-B stats once published, new tournament teams, etc. — see `MIGRACION.md` for the full checklist when a new regulation (Reg M-C…) drops.

**State/context layering** (all in `src/lib/` or `src/store/`, each exposes a hook):
- `store/teamStore.tsx` (`useTeam`) — saved teams, active team, edits; persisted to `localStorage`.
- `lib/auth.tsx` (`useAuth`) — login/register/logout, push/pull teams+replays to the cloud via `/api/*`.
- `lib/i18n.tsx` (`useLang`) — ES/EN toggle; `t()` translates via `lib/translations.ts` (Spanish text is the dictionary key) and applies Title Case (see below).
- `lib/seo.ts` (`useRouteSeo`) — per-route `<title>`/meta/OG since this is an SPA.

**Two "EV modes" coexist**: Champions *stat points* (0–32 per stat, 1 SP ≈ 8 EV) and traditional Showdown EVs (0–252). `src/lib/stats.ts` (`calcAllStats`, `convertInvestment`, `toTraditionalEvs`) is the single source of truth for converting between them — always go through it rather than hand-rolling EV math.

**Damage calc** (`src/lib/damageCalc.ts`) wraps `@smogon/calc` with app-specific `CalcMon`/`FieldState`/`SideState` types, and hand-codes Champions-only mechanics (Z-A abilities like Fire Mane/Dragonize not supported by the calc library, spread-move ×0.75 via `FieldState.singleTarget`, etc.).

**Translation model**: `t(es: string)` in `lib/i18n.tsx` takes the *Spanish literal* used in JSX as its own key, looks up `TRANSLATIONS[es]` for English, and always applies title-casing (capitalize each word except minor words like "de", "la", "the", "of" — see `titleCase`/`MINOR_WORDS` in `lib/i18n.tsx`). When adding UI text, write the Spanish string inline in JSX wrapped in `t(...)`, then add the EN value to `lib/translations.ts` if needed — do not invent new keys elsewhere.

**Hidden/dev-only pages**: nav items in `src/components/Layout.tsx` can be marked `dev: true`; `src/lib/devPages.ts` (`canSeeDevPages`) gates them to `import.meta.env.DEV` or an admin user (`user.isAdmin`, computed server-side in `functions/_lib/auth.ts` from the `ADMIN_EMAILS` env var). Both the nav link and the route need the same gate.

**Shared animation/UI primitives** worth reusing instead of re-implementing:
- `src/lib/useFlip.ts` — FLIP list-reorder animation (used in Pokédex, Speed Tier, tournament teams); pass `enabled=false` for large lists (>~60 items) to avoid measuring cost.
- `src/components/Combobox.tsx`, `Dropdown.tsx`, `SegmentedControl.tsx`, `Modal.tsx` — reusable search/select/tab/modal components with the app's dark theme; prefer these over ad-hoc `<select>`/custom dropdowns.
- Keyframes and utility classes (`.panel`, `.btn-primary`, `.mega-badge`, `.range-poke`, etc.) live in `src/index.css`; all respect `prefers-reduced-motion`.

**Cloudflare Functions** (`functions/api/**`, shared helpers in `functions/_lib/auth.ts`) only run in production or under `wrangler pages dev` — never during `vite dev`. Auth is cookie-session based (PBKDF2 password hash, D1 tables `users`/`sessions`/`teams`/`user_replays`/`login_attempts`, binding name `DB`). Required env vars (Cloudflare Pages dashboard, not in repo): `SESSION_SECRET`, `ADMIN_EMAILS`, plus `CLOUDFLARE_DEPLOY_HOOK` as a GitHub Actions secret for the daily data-refresh workflow (`.github/workflows/refresh-data.yml`).

**PWA caching** (`vite.config.ts`, `vite-plugin-pwa`): sprites are `CacheFirst`; `/data/*` JSON is `NetworkFirst` (data changes daily — don't switch this to `StaleWhileRevalidate`/long `max-age`, it previously caused stale tournament data to stick for users). `public/_headers` also sets `/data/*` to `Cache-Control: no-cache` so the browser HTTP cache revalidates via ETag on every load.
